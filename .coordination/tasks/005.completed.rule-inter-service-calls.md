# Task 005: rule-inter-service-calls

**Type:** code
**Dependencies:** 001

## Goal
Write `.claude/rules/inter-service-calls.md` — how one service calls another. The repo has
TWO divergent styles; this rule names the CORRECT one (`Clients/` + `IHttpClientFactory` +
bearer forwarding + timeout) and marks the WRONG one (`ServiceCalls/` + `new HttpClient()` +
`.Result`). Also covers the named-client registration + `appsettings` "Services" config.

## Findings

### CORRECT style — `Clients/` with `IHttpClientFactory`
- `ProblemService/Clients/LoggerServiceClient.cs:12` — `IHttpClientFactory` injected, `factory.CreateClient("LoggerService")`
- `ProblemService/Clients/LoggerServiceClient.cs:24` — bearer forwarded via `AuthenticationHeaderValue.Parse(bearerHeader)`
- `ProblemService/Clients/LoggerServiceClient.cs:29-32` — linked `CancellationTokenSource(800ms)` + `await SendAsync`
- `ProblemService/Clients/LoggerServiceClient.cs:26-27` — `System.Text.Json` (`JsonContent.Create`, `JsonSerializerDefaults.Web`)
- 10 copies confirmed: `AnonymousUserService/Clients/LoggerServiceClient.cs`, `AttachmentService/Clients/LoggerServiceClient.cs`, `BillingNotificationService/Clients/LoggerServiceClient.cs`, `OrganizationService/Clients/LoggerServiceClient.cs`, `ProblemBoxService/Clients/LoggerServiceClient.cs`, `SuggestionService/Clients/LoggerServiceClient.cs`, `SuggestionBoxService/Clients/LoggerServiceClient.cs`, `SubscriptionService/Clients/LoggerServiceClient.cs`, `SystemNotificationService/Clients/LoggerServiceClient.cs`

### WRONG style — `ServiceCalls/` with `new HttpClient()` + `.Result`
- `ProblemService/ServiceCalls/AttachmentService.cs:17` — `new HttpClient()` per call (socket exhaustion)
- `ProblemService/ServiceCalls/AttachmentService.cs:20` — `.GetAsync(url).Result` (sync-over-async / deadlock risk)
- `ProblemService/ServiceCalls/AttachmentService.cs:25` — `.ReadAsStringAsync().Result` (second `.Result` block)
- `ProblemService/ServiceCalls/AttachmentService.cs:23` — `return null` on non-2xx (silent failure)
- `ProblemService/ServiceCalls/AttachmentService.cs:1,26` — `Newtonsoft.Json.JsonConvert` (inconsistent serializer)
- `ProblemBoxService/ServiceCalls/ProblemService.cs:18` — `new HttpClient()` per call
- `ProblemBoxService/ServiceCalls/ProblemService.cs:21,26` — `.GetAsync().Result` + `.ReadAsStringAsync().Result`
- `ProblemBoxService/ServiceCalls/ProblemService.cs:1,27` — `Newtonsoft.Json.JsonConvert`
- `SuggestionService/ServiceCalls/UserServiceCall.cs:19` — reads wrong config key `ServiceUrls:OrganizationService`; appsettings uses `"Services"` block, not `"ServiceUrls"` → always `null` at runtime

### Registration (`AddHttpClient` + `appsettings.json`)
- `ProblemService/Program.cs:27-30` — `AddHttpClient("LoggerService", ...)` with `Services:LoggerServiceBaseUrl`
- `ProblemService/Program.cs:32-35` — `AddHttpClient("AttachmentService", ...)` with `Services:AttachmentService`
- `ProblemService/Program.cs:37-40` — `AddHttpClient("OrganizationService", ...)` with `Services:OrganizationService` (MISMATCH: appsettings key is `"UserService"`)
- `ProblemService/appsettings.json:13-15` — `"Services"` block with `AttachmentService`, `UserService`, `LoggerServiceBaseUrl`
- `SubscriptionService/Program.cs:35-47` — three `AddHttpClient` registrations for `OrganizationService`, `BillingNotificationService`, `LoggerService`
- `ProblemBoxService/appsettings.json:9,16` — **duplicate `"Services"` key**; second key wins, first entry (`ProblemService` URL) is silently discarded

### Gotcha — inconsistent key names
- `ProblemService/Program.cs:38` reads `Services:OrganizationService` but `ProblemService/appsettings.json:14` has `"UserService"` → startup may throw or return `null`
- `SuggestionService/ServiceCalls/UserServiceCall.cs:19` reads `ServiceUrls:OrganizationService` but `SuggestionService/appsettings.json:10` key is `Services:OrganizationService` → always `null`
- `ProblemBoxService/appsettings.json:9,16` — duplicate `"Services"` block; `ProblemService` URL never seen at runtime

## Solution

The rule file `.claude/rules/inter-service-calls.md` was written to document the two divergent
inter-service HTTP styles (CORRECT: `Clients/` with `IHttpClientFactory` + async + bearer
forwarding; WRONG: `ServiceCalls/` with `new HttpClient()` + `.Result`), the named
`AddHttpClient` registration pattern, the `appsettings.json` `"Services"` block convention,
and three critical config-key mismatches that cause silent `null` or startup failures.
