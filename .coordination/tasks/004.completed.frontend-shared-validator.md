# Task 004: frontend-shared-validator

**Type:** code
**Dependencies:** none

## Goal
Create the single source of truth for client-side validation: a shared validator module and a HIBP
soft-check helper. Tasks 005 and 006 import these — so the API and the returned messages must match
the Shared Contract exactly.

## Acceptance criteria
- [ ] New `Frontend/reporting-app/src/utils/validation.js` exporting:
  - `validateEmail(email) -> { valid: boolean, message: string }` — lowercases + trims, tests
    `^[^\s@]+@[^\s@]+\.[^\s@]+$`. Invalid message: `Please enter a valid email address.`
  - `validatePassword(password) -> { valid, message }` — length 8..64 + complexity regex
    `^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[^A-Za-z0-9]).{8,64}$`. Returns the canonical message for the
    FIRST failing rule: too short → `Password must be at least 8 characters.`; too long →
    `Password must be at most 64 characters.`; complexity → `Password must include uppercase,
    lowercase, a number, and a special character.` Do NOT trim internal spaces.
  - `validateUsername(username) -> { valid, message }` — `^[a-zA-Z0-9_]+$`, length 3–30. Invalid
    message: `Username may only contain letters, digits, and underscores (3–30 chars).`
  - All `valid:true` cases return `message: ''`.
- [ ] New `Frontend/reporting-app/src/services/pwnedService.js` exporting an async
  `checkPwned(password) -> 'breached' | 'safe' | 'unknown'` that does the k-anonymity range request:
  SHA-1 the password (use Web Crypto `crypto.subtle.digest('SHA-1', ...)`), hex-encode UPPERCASE,
  take first 5 chars as prefix, `fetch('https://api.pwnedpasswords.com/range/' + prefix)`, search
  response text lines for the 35-char suffix. **This MUST NOT use `API_BASE_URL`** — it hits the
  external HIBP host directly, not the gateway. On ANY network/fetch error → return `'unknown'`
  (fail open). Found → `'breached'`; not found → `'safe'`.
- [ ] No other files changed in this task. (005/006 wire these in.)
- [ ] Module is plain ES modules consistent with the other files in `src/services/` and `src/utils/`
  (named exports, no default unless natural). `src/utils/` does not exist yet — create it.

## Context
- **Messages must be byte-identical to the backend** (Tasks 001/002) and to the Shared Contract
  table in `.coordination/PLAN.md`. This is the anti-drift seam.
- **Error shape reuse:** the existing `extractErrorMessage` in `src/services/userService.js:8-18`
  already parses backend errors; do not introduce a new shape. This task only produces client-side
  validators + the HIBP helper; surfacing backend errors stays in the form components.
- **Gateway base:** other services use `const API_BASE_URL = 'http://127.0.0.1:80'` (plain HTTP).
  `pwnedService.js` deliberately does NOT use it.
- **Web Crypto availability:** `crypto.subtle` requires a secure context; `localhost`/`127.0.0.1`
  count as secure, so it works in dev. SHA-1 hashing example:
  `const buf = await crypto.subtle.digest('SHA-1', new TextEncoder().encode(password));`
  then map bytes to hex and `.toUpperCase()`.
- Suggested optional unit test (if a test harness is convenient): the project uses CRA + Jest
  (`npm test`); a small `validation.test.js` asserting each canonical message is a nice-to-have, not
  required.

## Self-check
- `validatePassword('abc')` → `{valid:false, 'Password must be at least 8 characters.'}`
- `validatePassword('alllowercase1!')` → complexity message (no uppercase).
- `validatePassword('Zx9$mQ2!vK7w')` → `{valid:true, ''}`.
- `validateUsername('ab')` → username message; `validateUsername('good_name1')` → valid.
- `checkPwned('password')` → `'breached'`; offline → `'unknown'`.

## Solution
Added `Frontend/reporting-app/src/utils/validation.js` (`validateEmail`/`validatePassword`/`validateUsername`,
canonical messages verbatim, first-failing-rule for password, no internal trimming) and
`Frontend/reporting-app/src/services/pwnedService.js` (`checkPwned` → 'breached'|'safe'|'unknown', Web Crypto
SHA-1 uppercase, hits HIBP directly not the gateway, fail-open to 'unknown'). `npm run build` succeeded (only
pre-existing unrelated lint warnings). Inputs coerced via `String(x ?? '')` for robustness.
