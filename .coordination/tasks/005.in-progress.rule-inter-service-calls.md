# Task 005: rule-inter-service-calls

**Type:** code
**Dependencies:** 001

## Goal
Write `.claude/rules/inter-service-calls.md` — how one service calls another. The repo has
TWO divergent styles; this rule names the CORRECT one (`Clients/` + `IHttpClientFactory` +
bearer forwarding + timeout) and marks the WRONG one (`ServiceCalls/` + `new HttpClient()` +
`.Result`). Also covers the named-client registration + `appsettings` "Services" config.

## Acceptance criteria
- [ ] File `.claude/rules/inter-service-calls.md` created, <500 lines.
- [ ] Findings lists 3+ real `file:line` per pattern, including BOTH styles.
- [ ] CORRECT pattern (from `LoggerServiceClient`): inject `IHttpClientFactory`,
      `factory.CreateClient("Name")`, forward `Authorization` header via
      `AuthenticationHeaderValue.Parse(bearerHeader)`, linked `CancellationTokenSource`
      timeout, async `SendAsync`.
- [ ] WRONG pattern (from `ServiceCalls/AttachmentService.cs`): `new HttpClient()` per call,
      `.Result` (sync-over-async / deadlock risk), no bearer forwarding, swallowed null on
      non-2xx. Explain WHY it's wrong (socket exhaustion, blocking, lost auth context).
- [ ] Registration: named `AddHttpClient("LoggerService", c => c.BaseAddress = new Uri(
      builder.Configuration["Services:LoggerServiceBaseUrl"]!))` in `Program.cs`, and the
      matching `"Services"` keys in `appsettings.json`.
- [ ] Note the audit-log client (`TryLogAsync`) is the reference implementation — link to
      task 002 (controllers-and-errors) for the call-site usage.
