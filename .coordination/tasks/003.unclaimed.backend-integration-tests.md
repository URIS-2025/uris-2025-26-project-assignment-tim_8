# Task 003: backend-integration-tests

**Type:** code
**Dependencies:** 001, 002

## Goal
Prove the backend is the real gate end-to-end with `WebApplicationFactory` integration tests for
both services: weak/breached/bad-format requests are rejected with `400 { error }`; valid requests
are accepted; HIBP network failure fails open.

## Acceptance criteria
- [ ] Integration tests for `POST /api/User/` (OrganizationService) covering: malformed email →
      `400 { error: "Please enter a valid email address." }`; weak password (missing a class) →
      `400` with the complexity message; breached password → `400` with the breached message;
      valid strong+unique → `201`.
- [ ] Integration tests for `POST /api/AnonymousUser/` (AnonymousUserService) covering: bad username
      → `400` with the username message; weak password → `400` complexity; breached → `400` breached;
      valid → `201`. **Explicitly assert the response body shape is `{ "error": ... }` (not
      `{ "message": ... }`)** — this guards the Task 002 controller fix from regressing.
- [ ] HIBP is mocked/stubbed in the test host so tests are deterministic and offline: register a
      fake `IPwnedPasswordsClient` (or test HttpMessageHandler) in the test `WebApplicationFactory`
      that returns "breached" for a designated password and "not breached" otherwise, plus one test
      where it throws → request still `201` (fail open).
- [ ] Tests use the `Testing` environment so `db.Database.Migrate()` is skipped (see both
      `Program.cs`: `if (!app.Environment.IsEnvironment("Testing")) db.Database.Migrate();`) and use
      EF InMemory or the existing integration-test DB setup pattern.
- [ ] `dotnet test` passes for the affected test projects.

## Context
- **Existing patterns to copy:** look at other `*IntegrationTests` projects in the solution
  (`ProblemServiceIntegrationTests`, `ProblemBoxServiceIntegrationTests`,
  `LogerServiceIntegrationTests`) for the `WebApplicationFactory<Program>` + `Testing` environment
  + service-replacement (`WithWebHostBuilder` / `ConfigureTestServices`) idiom. `Program` is exposed
  via `public partial class Program { }` at the bottom of each `Program.cs`.
- Both services register a `"PwnedPasswords"` named HttpClient + typed `PwnedPasswordsClient`
  (Tasks 001/002). In the test factory, replace the typed client (or its `IPwnedPasswordsClient`
  interface) with a fake to control breached/not/throw outcomes without real network calls.
- Canonical messages and the `{ error }` shape are in `.coordination/PLAN.md` (Shared Contract).
- Place tests in the existing `OrganizationServiceTests` and `AnonymousUserServiceTest` projects, or
  in the `*IntegrationTests` projects if you prefer separation — match whatever the dependency tasks
  set up so projects build together.

## Why this is separate from 001/002
Unit tests (mocked validator/client) live inside 001 and 002. This task does the through-the-HTTP-
pipeline verification that the controller → repo → 400-shape wiring actually holds for BOTH services
at once, which is exactly the "bypass test" in the plan's Verification section.
