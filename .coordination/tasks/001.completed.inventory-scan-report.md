## Required sections
1. **Service inventory** — table: service | `.cs` file count | one-line purpose. All 11:
   AnonymousUserService, OrganizationService, ProblemService, ProblemBoxService,
   SuggestionService, SuggestionBoxService, SubscriptionService,
   BillingNotificationService, SystemNotificationService, AttachmentService, LoggerService.
2. **Shared code** — there is NO shared csproj/project. The `AnonymousDomain.Models.*`
   namespace is **copy-duplicated** across 20 model files in different services
   (`grep -rl "namespace AnonymousDomain"`). Document this as a gotcha, not a library.
3. **Inter-service communication** — two divergent REST styles:
   - `Clients/` (e.g. `ProblemService/Clients/LoggerServiceClient.cs`) — `IHttpClientFactory`,
     forwards bearer header, 800ms timeout, swallows errors.
   - `ServiceCalls/` (e.g. `ProblemService/ServiceCalls/AttachmentService.cs`) — raw
     `new HttpClient()` + `.Result` (sync-over-async), no bearer, `JsonConvert`.
   Named HttpClients registered in each `Program.cs` via `AddHttpClient("Name", ...)`;
   target URLs in `appsettings.json` under `"Services"`.
4. **Auth/security** — JWT bearer configured ONLY in `AnonymousUserService/Program.cs`
   and `OrganizationService/Program.cs` (`AddAuthentication(JwtBearerDefaults...)`).
   `[Authorize]` appears in 6 controllers (15 occurrences). Rate limiting (`AddRateLimiter`,
   `login`/`register` policies) ONLY in `AnonymousUserService/Program.cs`. Password hashing
   + JWT issuance in `AnonymousUserService/Data/AnonymousUserRepository.cs` and
   `OrganizationService/Data/UserRepository.cs` (`System.Security.Cryptography`,
   `JwtSecurityToken`). Most services do NOT validate JWTs at all.
5. **Error shape** — controllers catch and return `new { error = ex.Message }` via
   `BadRequest`/`NotFound` (52 occurrences, 19 controllers). Global `UseExceptionHandler`
   in `Program.cs` returns `new { message = error.Error.Message }` with 500. Note the
   `error` vs `message` key mismatch.
6. **DB/ORM** — EF Core, SQL Server, one DbContext + DB per service. `Database.Migrate()`
   (or `EnsureCreated()` for non-relational/test) runs at startup in every `Program.cs`.
   Connection string key is service-specific (`"ProblemDB"`, `"AnonymousUserDB"`, ...).
   Query style: repositories return DTOs via manual `IMapper.Map` loops; `SaveChanges()`
   returns `bool` (`_context.SaveChanges() > 0`). No explicit transactions observed.
7. **Observability** — no tracing/metrics. Logging is the centralized LoggerService:
   controllers fire `_loggerClient.TryLogAsync(new LogCreationDTO {...})`. Document the
   `LogCreationDTO` field set from `LoggerService/Models/DTOs/LogCreationDTO.cs`
   (UserId, Action, EntityName, OldValues, NewValues, IsSuccess, ServiceName, HttpMethod).
8. **5–10 recurring load-bearing patterns** with grep evidence (use the greps below).
9. **Proposed rule files (6)** and **guide files (4)** — list with one-line scope, matching
   the slugs in PLAN.md.
