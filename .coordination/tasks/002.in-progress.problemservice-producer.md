# Task 002: ProblemService Notification Producer (Agent A)

**Type:** code
**Dependencies:** 001

## Goal
Make ProblemService produce a **system notification** when (a) a new problem is submitted and (b) a new problem comment is created — by any author. Resolve the owning `organizationId` by looking up the problem's `BoxId` against `ProblemBoxService`, then fire a non-fatal notification call forwarding the caller's JWT. Add unit tests.

## Acceptance criteria
- [ ] New problem submitted → exactly one system notification created with the resolved `OrganizationId` and a sensible `Text` (e.g. "A new problem was submitted.").
- [ ] New problem comment created → exactly one system notification with resolved `OrganizationId`, `ProblemCommentId` set, sensible `Text`.
- [ ] Org-id resolved via `GET api/ProblemBox/{boxId}` → `OrganizationId`. If the box lookup fails/returns null, the notification is skipped and the create still succeeds (no throw).
- [ ] Notification call is non-fatal (try/catch-swallow, per task 001 contract) — a notification failure never breaks problem/comment creation.
- [ ] Caller's `Authorization` header forwarded to both the box lookup and the notification call.
- [ ] Named `HttpClient`s for `ProblemBoxService` and `SystemNotificationService` registered in `Program.cs`; URLs added to `appsettings.json` `Services` section.
- [ ] Unit tests (xUnit + Moq, in `ProblemServiceTests/`): notification client called once with correct resolved org-id on create; box-missing → no notification + no throw; notification-client-throws → underlying create still succeeds.
- [ ] `dotnet build` and the ProblemService tests pass.

- Controllers to instrument: `ProblemService/Controllers/ProblemController.cs` (new problem POST) and `ProblemService/Controllers/ProblemCommentController.cs` (new comment POST). Mirror how these already call `LoggerServiceClient.TryLogAsync` (the logger client is injected and the `Authorization` header forwarded in the existing POST actions).
- Existing client to mirror: `ProblemService/Clients/LoggerServiceClient.cs` (the `TryLogAsync` non-fatal pattern). Existing duplicated DTO: `ProblemService/Clients/LogCreationDTO.cs` — create `Clients/SystemNotificationCreationDTO.cs` the same way.
- New clients to add under `ProblemService/Clients/`:
  - `ProblemBoxServiceClient` — `GET /api/ProblemBox/{id}`, deserialize to a minimal DTO exposing `OrganizationId`; return `null` on failure (non-throwing).
  - `SystemNotificationServiceClient` — `POST /api/SystemNotification`, non-fatal `TryNotifyAsync(SystemNotificationCreationDTO, bearer, ct)`.
- System notification DTO fields (local copy): `Text`, `OrganizationId (Guid?)`, `AnonymousUserId (Guid?)`, `ProblemCommentId (Guid?)`, `SuggestionCommentId (Guid?)`. For a problem-comment event set `ProblemCommentId`; leave `SuggestionCommentId` null.

Confirm the exact key names by reading the current `ProblemService/Program.cs` + `appsettings.json`.
- The problem entity carries `BoxId` (a problem box id), not an org id — that's why the box lookup is required. A comment carries its parent problem id; resolve problem → `BoxId` → box → org (you may need the problem repo/lookup to get `BoxId` from the comment's problem id).

## Gotchas
- Do NOT make the org lookup or notification fatal — wrap in try/catch and skip on failure.
- Keep the wire body to the fields the receiver binds (task 001 contract).
- Tests use `EF InMemory` + Moq like the rest of `ProblemServiceTests/`; mock the notification/box clients (extract small interfaces if needed so they're mockable).

## Findings / Solution

ProblemService now produces a **system notification** on (a) new problem submitted and
(b) new problem comment created — following the task 001 contract.

**New files (`ProblemService/Clients/`):**
- `SystemNotificationCreationDTO.cs` — local DTO copy (`Text`, `OrganizationId?`,
  `AnonymousUserId?`, `ProblemCommentId?`, `SuggestionCommentId?`).
- `SystemNotificationServiceClient.cs` — non-fatal `virtual TryNotifyAsync(dto, bearer, ct)`,
  `POST /api/SystemNotification`, try/catch-swallow + 800 ms timeout (mirrors
  `LoggerServiceClient`). Parameterless ctor + `virtual` so it's Moq-able.
- `ProblemBoxServiceClient.cs` — non-fatal `virtual Task<Guid?> TryGetOrganizationIdAsync(
  boxId, bearer, ct)`, `GET /api/ProblemBox/{id}`, returns `null` on missing/non-2xx/error.
- `ProblemBoxVO.cs` — minimal projection exposing `OrganizationId`.

**Controllers:**
- `ProblemController.CreateProblem` → after create, `NotifyProblemSubmittedAsync(result)`:
  resolve org from `result.ProblemBoxId`, send `Text="A new problem was submitted."` +
  `OrganizationId`. Skips silently if org unresolved. Both new clients injected.
- `ProblemCommentController.CreateProblemComment` → after create,
  `NotifyCommentCreatedAsync(result)`: resolve via `IProblemRepository.GetProblemById(
  result.ProblemId).ProblemBoxId` → box → org, send `Text="A new comment was added to a
  problem."` + `OrganizationId` + `ProblemCommentId=result.Id`. Injects `IProblemRepository`
  + both clients. Skips silently if problem/box unresolved.
- Both helpers are themselves wrapped in try/catch and the caller's
  `Request.Headers["Authorization"]` is forwarded to box lookup AND notification call.

**Wiring:**
- `Program.cs`: registered scoped `SystemNotificationServiceClient` + `ProblemBoxServiceClient`
  and named HttpClients `"SystemNotificationService"` / `"ProblemBoxService"`.
- `appsettings.json` `Services`: `SystemNotificationService=http://system-notification-service:8080/`,
  `ProblemBoxService=http://problem-box-service:8080/`.

**Tests** (`ProblemServiceTests/`, xUnit + Moq; clients mocked via `virtual`):
- `ProblemTests.cs` + `ProblemCommentTests.cs` updated for new ctors (+ `DefaultHttpContext`
  so `Request.Headers`/`User` resolve).
- Per controller: notification sent once with resolved org-id (and `ProblemCommentId` for
  comments); box-missing → notification `Times.Never` + still `Created`; notification throws
  → still `Created`.

**Verification:** `dotnet build ProblemServiceTests` → 0 errors. `dotnet test` (controller
filter) → **22 passed, 0 failed**.

notification, so the duplicate frontend create in `SubmissionDetails.jsx` can be removed.
