# Task 011: guide-cross-service-contracts

**Type:** both
**Dependencies:** 001

## Goal
Write `.claude/guides/cross-service-contracts.md` — the dynamic wiring between services: who
calls whom, over which named HttpClient, configured by which `appsettings` key; the centralized
LoggerService log contract; and the duplicated-model gotcha that makes these contracts brittle.

## Acceptance criteria
- [ ] File `.claude/guides/cross-service-contracts.md` created.
- [ ] "Sources" section lists every file read.
- [ ] Call graph table: caller service | callee | mechanism (`Clients/` factory vs `ServiceCalls/`
      raw) | named client | `appsettings` "Services" key | auth forwarded? (yes/no).
- [ ] LoggerService contract: document `LogCreationDTO` fields (UserId, Action, EntityName,
      OldValues, NewValues, IsSuccess, ServiceName, HttpMethod) and the `POST /api/logger`
      endpoint; note EVERY service calls it fire-and-forget via its own `LoggerServiceClient` copy.
- [ ] Value-object contracts: `AttachmentVO`, `ProblemCommentAuthorUserVO` — DTOs a service
      defines to deserialize ANOTHER service's response. Note they are hand-maintained copies,
      so a producer-side change silently breaks consumers (gotcha).
- [ ] Duplicated `AnonymousDomain` models: 20 model files share the namespace across services
      with no shared project — changing an entity means editing N copies. This is THE central
      contract risk; give it a prominent gotcha box.
- [ ] Config reference: the `"Services"` block keys per service and their Docker URLs
      (`http://<container>:8080/`), noting key-name inconsistencies.
