## Findings
**VERDICT: CONCERNS.** Core validation logic is correct, byte-identical, well-tested, and fails open
correctly. BUT a dual-validation-layer defect breaks the Shared Contract for several inputs.

PASS items: byte-identical shared files (namespace-only diff); canonical messages verbatim in repo throws;
exact regexes; validation before BCrypt; fail-open (`PwnedPasswordsClient` bare `catch { return false; }`);
controller mapping (anon now `catch (ArgumentException)->400 {error}`, org via generic catch); no scope creep;
all NEW validation/integration tests pass (pre-existing 401 [Authorize] integration failures + 1 stale
DeleteAnonymousUser test are unrelated).

**CONCERN — dual validation layers:** `UserCreationDTO.cs` and `AnonymousUserCreationDTO.cs` carry DataAnnotations
with NON-canonical messages and a DIVERGENT password regex (org `^(?=.*[A-Z])(?=.*[0-9])(?=.*[^a-zA-Z0-9]).+$` —
no lowercase lookahead, no length) and `Username MaxLength(150)`. `[ApiController]` auto-returns
`400 { errors: {...} }` (ProblemDetails) BEFORE the repo's canonical `{ error }` runs. So missing fields, malformed
emails caught by `[EmailAddress]`, short/long passwords, and most complexity failures return the WRONG shape and
WRONG message; the canonical repo gate is only hit for inputs that pass annotations but fail the stricter repo rules.

**Recommendation (option 1, matches the plan):** remove the overlapping format/length/regex/[EmailAddress]
annotations so the repo is the single source of truth; add `ConfigureApiBehaviorOptions(SuppressModelStateInvalidFilter=true)`
and null/empty guards so every rejection is canonical `{ error }`. Update the substring-asserting integration test
(`AnonymousUserValidationIntegrationTests.cs:105`) to strict. This also fixes the org email message ("provide" vs
canonical "enter"). → Tracked as follow-up Task 010.
