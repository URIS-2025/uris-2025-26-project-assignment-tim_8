# Task 006: rule-auth-jwt

**Type:** code
**Dependencies:** 001

## Goal
Write `.claude/rules/auth-jwt.md` — where auth lives and how to add it. JWT bearer is
configured in ONLY 2 services; `[Authorize]` is sparse; rate limiting lives in ONE service.
This rule must make clear what exists and the load-bearing config (validation params,
hashing, rate-limit policies) — NOT prescribe new auth.

## Acceptance criteria
- [ ] File `.claude/rules/auth-jwt.md` created, <500 lines.
- [ ] Findings lists 3+ real `file:line` per pattern.
- [ ] Covers:
      - JWT registration block: `AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
        .AddJwtBearer(...)` with `TokenValidationParameters` (ValidateIssuer/Audience/Lifetime/
        IssuerSigningKey) reading `Jwt:Issuer`/`Jwt:Audience`/`Jwt:Key` from config.
      - Pipeline order: `UseAuthentication()` BEFORE `UseAuthorization()`.
      - `[Authorize]` placement (controller/action level) — list the 6 controllers that use it.
      - Token issuance + password hashing location (repos, not controllers) — real method names.
      - Rate-limit policies (`login`: 5/min, `register`: 3/hr) partitioned by
        `X-Forwarded-For`, with `OnRejected` → 429 `{ error }`. Requires `UseForwardedHeaders`.
- [ ] WRONG/CORRECT: adding `[Authorize]` to a controller in a service whose `Program.cs`
      has NO `AddAuthentication` (the attribute is a no-op / 500s) — must add JWT wiring first.
