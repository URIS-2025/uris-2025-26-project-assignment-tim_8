# Task 006: frontend-anon-signup-gates

**Type:** code
**Dependencies:** 004

## Goal
Replace the cosmetic password-strength logic in the anonymous signup form with real hard gates from
the shared validator, plus username + confirm-match + HIBP soft-check. Keep the strength meter as
UX only.

## Acceptance criteria
- [ ] In `Frontend/reporting-app/src/pages/AnonymousSignup.jsx` import `validatePassword`,
      `validateUsername` from `../utils/validation` and `checkPwned` from `../services/pwnedService`.
- [ ] `handleSubmit` (`:25-56`) enforces, in order, after `e.preventDefault()`/`setError('')`:
      `validateUsername(username)` → `validatePassword(password)` → confirm-match
      (`password !== confirmPassword` → `setError('Passwords do not match.')`) →
      `await checkPwned(password)`: `'breached'` →
      `setError('This password has appeared in a data breach. Please choose another.')` + return;
      `'unknown'` → proceed. Each validator failure → `setError(message)` + return, NO network call.
- [ ] **Remove the ad-hoc gates** currently at `:32-45` (the `length < 8` check at `:37` and the
      raw `password !== confirmPassword` check) — they are superseded by the shared validator and the
      canonical confirm-match message. Keep the "all fields present" guard or fold it into the
      validators (empty username/password will already fail the validators — but an explicit
      `Please fill in all fields.` for empty inputs is acceptable to keep).
- [ ] **Keep the strength meter** (`passwordStrength` helper `:7-15` + the meter UI `:118-122`) for
      UX feedback, but it must NOT be the gate — submission is gated by `validatePassword`. You may
      leave the cosmetic `passwordStrength` regex as-is (it's display-only now).
- [ ] Keep the existing inline error block (`:75-85`). Submit button (`disabled={isSubmitting}`)
      must not get stuck — only set `setIsSubmitting(true)` after gates pass (the existing code sets
      it inside `try` at `:48`, which is already after the guards — preserve that ordering).
- [ ] On success, keep `navigate('/anonymous/login')` (`:50`).
- [ ] `npm run build` succeeds.

## Context
- Current `handleSubmit` (`AnonymousSignup.jsx:25-56`): reads `username` (`:29`,
  `e.target.username.value.trim()`) and `confirmPassword` (`:30`); `password` is component state
  (`:21`, controlled input `:113-115`). Guards: all-fields (`:32-35`), `length < 8` (`:37-40`),
  mismatch (`:42-45`). Then `try { setIsSubmitting(true); await AnonymousUserService.create(...) }`.
- The username input already has `pattern`/`minLength`/`maxLength` HTML attrs (`:96-99`) but
  `handleSubmit` never enforces them in JS — `validateUsername` makes the gate real.
- Anonymous users have NO email — only username + password.
- Messages come from Task 004's validator (canonical); don't hand-write them except the
  fill-all-fields helper.
- `checkPwned` returns `'breached' | 'safe' | 'unknown'`; only `'breached'` blocks (fail open).
- Do NOT touch routing/AuthContext/token storage.

## Self-check
- Bad username (too short / bad chars) → inline username message, no network call.
- Weak password → complexity/length message; mismatch → `Passwords do not match.`
- Breached-but-complex password → breach warning, blocked.
- Strength meter still updates as the user types (UX), but does not by itself allow/block submit.
