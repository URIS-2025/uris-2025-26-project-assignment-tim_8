# Task 003: SuggestionService Notification Producer (Agent B)

**Type:** code
**Dependencies:** 001

## Goal
Make SuggestionService produce a **system notification** on three events: (a) a new suggestion submitted, (b) a new suggestion comment (any author), and (c) a new vote on a suggestion. Resolve the owning `organizationId` via `SuggestionBoxService`, then fire a non-fatal notification call forwarding the caller's JWT. Add unit tests.

## Acceptance criteria
- [ ] New suggestion submitted → one system notification with resolved `OrganizationId` + sensible `Text`.
- [ ] New suggestion comment → one system notification with resolved `OrganizationId`, `SuggestionCommentId` set, sensible `Text`.
- [ ] New vote → one system notification with resolved `OrganizationId` + sensible `Text` (e.g. "A suggestion received a new vote.").
- [ ] Org-id resolved via `GET api/SuggestionBox/{boxId}` → `OrganizationId`. Box lookup failure/null → notification skipped, underlying create still succeeds (no throw).
- [ ] Notification call non-fatal (task 001 contract); caller's `Authorization` header forwarded to box lookup + notification call.
- [ ] Named `HttpClient`s for `SuggestionBoxService` and `SystemNotificationService` registered in `Program.cs`; URLs in `appsettings.json` `Services` section.
- [ ] Unit tests (xUnit + Moq, in `SuggestionServiceTests/`): notification client called once per event with correct resolved org-id; box-missing → no notification + no throw; notification-client-throws → underlying create still succeeds; vote path covered.
- [ ] `dotnet build` and the SuggestionService tests pass.

## Context

- **Read task 001's "Findings / Solution" first** — DTO shape, route, non-fatal client template, org-resolution rule.
- Controllers to instrument: `SuggestionService/Controllers/SuggestionController.cs` (new suggestion POST), `SuggestionService/Controllers/SuggestionCommentController.cs` (new comment POST), `SuggestionService/Controllers/VoteController.cs` (new vote POST). Mirror the existing `LoggerServiceClient.TryLogAsync` usage + `Authorization` forwarding already in these POST actions.
- Existing client to mirror: `SuggestionService/Clients/LoggerServiceClient.cs`; existing duplicated DTO `SuggestionService/Clients/LogCreationDTO.cs`. Add `Clients/SystemNotificationCreationDTO.cs` the same way.
- New clients under `SuggestionService/Clients/`:
  - `SuggestionBoxServiceClient` — `GET /api/SuggestionBox/{id}` → minimal DTO with `OrganizationId`; null on failure (non-throwing).
  - `SystemNotificationServiceClient` — non-fatal `TryNotifyAsync(SystemNotificationCreationDTO, bearer, ct)` → `POST /api/SystemNotification`.
- System notification DTO fields (local copy): `Text`, `OrganizationId (Guid?)`, `AnonymousUserId (Guid?)`, `ProblemCommentId (Guid?)`, `SuggestionCommentId (Guid?)`. For a suggestion-comment event set `SuggestionCommentId`; leave `ProblemCommentId` null. For suggestion/vote events leave both comment ids null.
- A suggestion carries `BoxId` (suggestion box id), not org id. Comment → parent suggestion → `BoxId` → box → org. Vote → suggestion → `BoxId` → box → org. You may need the suggestion repo to resolve `BoxId` from a comment's/vote's suggestion id.
- `Program.cs` registration: copy the existing `LoggerService` named-client idiom; confirm exact `Services:*` keys by reading `SuggestionService/Program.cs` + `appsettings.json`.
