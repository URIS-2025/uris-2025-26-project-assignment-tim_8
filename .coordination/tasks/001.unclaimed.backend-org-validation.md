two canonical shared source files — a `PasswordPolicy` validator and a `PwnedPasswordsClient`

## Context
- **Repo conventions (no `.claude/rules/` exists — these are the real patterns):**
  - Repositories are registered scoped in `Program.cs` and accessed via interfaces (`IUserRepository`).
  - Controllers map `InvalidOperationException -> 409 Conflict { error }` and (generic
    `catch (Exception)`) `-> 400 BadRequest { error }`. So a repo `ArgumentException` becomes
    `400 { error: "<message>" }` automatically — verified in `UserController.cs:63-80`.
  - Clients live in `Clients/`, use `IHttpClientFactory.CreateClient("Name")`, a linked
    `CancellationTokenSource` for timeout, and swallow failures. See
    `OrganizationService/Clients/LoggerServiceClient.cs` for the exact shape to mirror.
- **HIBP no bearer forwarding** — it's an external service; never attach the Authorization header.
- **HIBP self-check value:** the password `P@ssw0rd` (or `password`) is known-breached; a random
  strong string like `Zx9$mQ2!vK7w` is almost certainly not — useful for the curl test.
- **DTO:** `OrganizationService/Models/DTOs/UserCreationDTO.cs` carries `Email`, `Username`,
  `Password`, `Name`, `Surname`, `RoleId`, `OrganizationId`.
- **Rate limiting / audit logging / endpoints:** do NOT change. Register endpoint already has
  `[EnableRateLimiting("register")]`.
- **Egress note:** the Docker container needs outbound access to `api.pwnedpasswords.com`. The
  fail-open path keeps signups working if it's blocked — that is the intended behavior, not a bug.
