# Task 004: rule-program-bootstrap

**Type:** code
**Dependencies:** 001

## Goal
Write `.claude/rules/program-bootstrap.md` — the exact wiring every service's `Program.cs`
must have, in order: DbContext + connection string, repositories scoped, AutoMapper,
controllers + Swagger, named HttpClients, Kestrel on 8080, `Database.Migrate()` at startup.
This is the checklist for adding a NEW service or service feature.

## Acceptance criteria
- [ ] File `.claude/rules/program-bootstrap.md` created, <500 lines.
- [ ] Findings lists 3+ real `file:line` per claim.
- [ ] Covers, with a CORRECT skeleton block:
      - `AddDbContext<XxxContext>(o => o.UseSqlServer(builder.Configuration.GetConnectionString("XxxDB")))`
      - service-specific connection-string KEY (not a generic "DefaultConnection")
      - `AddAutoMapper(config => config.AddMaps(typeof(Program).Assembly))`
      - `AddScoped<IRepo, Repo>()` for each repository
      - `AddControllers()` + `AddEndpointsApiExplorer()` + `AddSwaggerGen()`
      - `builder.WebHost.ConfigureKestrel(o => o.ListenAnyIP(8080))` (ALL services use 8080)
      - startup migrate block: `using (var scope = app.Services.CreateScope()) { ... Database.Migrate(); }`
        — note the `IsRelational()`/`EnsureCreated()` and `IsEnvironment("Testing")` guards
      - `public partial class Program { }` at file end (required for WebApplicationFactory tests)
- [ ] EF migration workflow as a short table: `dotnet ef migrations add <Name>`,
      `dotnet ef database update`; migrations live in `<Service>/Migrations/`.
- [ ] WRONG/CORRECT: forgetting `partial class Program` (breaks integration tests),
      hardcoding port, using `EnsureCreated` in production path.
