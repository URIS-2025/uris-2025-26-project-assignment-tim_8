# Task 007: rule-gateway-routing

**Type:** code
**Dependencies:** 001

## Goal
Write `.claude/rules/gateway-routing.md` — how to expose a new controller through the Nginx
gateway. Every controller needs a matching `location /api/<Controller>/` block in
`gateway/nginx.conf` with the repeated CORS preamble and a container-name upstream on 8080.
Forgetting this = endpoint unreachable from the frontend.

## Acceptance criteria
- [ ] File `.claude/rules/gateway-routing.md` created, <500 lines.
- [ ] Findings cites 3+ real `location` blocks + the upstream list.
- [ ] CORRECT block template (copy from an existing `location`): the `OPTIONS` 204 short-circuit,
      the 3 `Access-Control-Allow-*` headers (Origin `*`, Methods, Headers `Content-Type,Authorization`),
      and `proxy_pass http://<upstream>/api/<Controller>/;`.
- [ ] Upstream rule: `upstream <name>_service { server <container-name>:8080; }` — container
      names are kebab-case (`problem-service`, `anonymous-user-service`), all port 8080.
- [ ] The proxy headers set once at `server` level: `Host`, `X-Real-IP`, `X-Forwarded-For`,
      `X-Forwarded-Proto` (the last two feed the rate limiter — link rule 006).
- [ ] WRONG/CORRECT: adding a controller without a `location` block; using `localhost`/service
      port instead of the container-name upstream; omitting the OPTIONS branch (CORS preflight fails).
- [ ] Note: CORS is duplicated per-block (no shared map) — adding a block means copying the
      full CORS preamble. Document this, don't refactor it.
