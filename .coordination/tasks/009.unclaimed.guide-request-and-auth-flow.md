# Task 009: guide-request-and-auth-flow

**Type:** both
**Dependencies:** 001

## Goal
Write `.claude/guides/request-and-auth-flow.md` — trace a request end to end and the auth
lifecycle. How a write request flows: browser → gateway → controller → repository → DbContext
→ DTO back; plus the fire-and-forget audit-log side-channel; plus the JWT issue/validate/refresh
path and where it is (and ISN'T) enforced.

## Acceptance criteria
- [ ] File `.claude/guides/request-and-auth-flow.md` created.
- [ ] "Sources" section lists every file read.
- [ ] Request lifecycle walkthrough using a REAL endpoint (`POST /api/Problem` →
      `ProblemController.CreateProblem` → `ProblemRepository.CreateProblem` → `SaveChanges` →
      `_mapper.Map<ProblemCreatedDTO>` → `Created`), including the parallel `TryLogAsync` call
      to LoggerService with forwarded bearer.
- [ ] Auth flow: where tokens are issued (`AnonymousUserService`/`OrganizationService` repos),
      what login returns (`{accessToken, refreshToken}`), how refresh tokens are stored
      (`RefreshToken` / `AnonymousRefreshToken` models), how validation works (JWT bearer in the
      2 services), and that most services do NOT validate — calls rely on the gateway being the
      only ingress. Call this out as a security gotcha.
- [ ] Rate-limit path: `login`/`register` policies keyed on `X-Forwarded-For` (set by gateway).
- [ ] Sequence-style numbered steps or an ASCII diagram. No invented middleware.
