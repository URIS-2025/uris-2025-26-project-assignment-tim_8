# Task 005: SubscriptionService Billing Producers (Agent D)

**Type:** code
**Dependencies:** 001

## Goal
Make SubscriptionService produce **billing notifications** for: plan/price change (fan-out to ALL orgs subscribed to that plan), payment success, payment failure, and subscription cancellation. Add a SubscriptionPlan **update** endpoint and a **subscriptions-by-planId** lookup to drive the fan-out. Make the existing subscription-create billing call **non-fatal**. Add unit tests.

## Acceptance criteria
- [ ] New `PUT api/SubscriptionPlan` update endpoint exists; on a plan/price change it fans out **one billing notification per org** that has a subscription to that plan.
- [ ] A "subscriptions by planId" lookup exists (repo method + the controller/code path that uses it) returning every subscription/org on a given plan.
- [ ] Payment success → billing notification to the paying org; payment failure → billing notification to the paying org. (Wire into `PaymentController` create/update.)
- [ ] Subscription cancellation → billing notification to that org. (Cancellation is currently `SubscriptionController.Delete` — confirm whether cancel == delete in this codebase and notify accordingly.)
- [ ] Existing subscription-**create** billing call made non-fatal: `BillingServiceCall.CreateBillingNotificationAsync` no longer throws on non-2xx (wrap like `TryLogAsync`); `SubscriptionController.Create` keeps working even if billing is down.
- [ ] All billing calls forward the caller's `Authorization` header (needed once task 006 adds `[Authorize]`).
- [ ] Unit tests (xUnit + Moq, in `SubscriptionServiceTests/`): plan-update fan-out creates N notifications for N subscribed orgs; payment success/fail each notify once; cancellation notifies once; non-fatal — billing client throws → underlying create/update/delete still succeeds.
- [ ] `dotnet build` and the SubscriptionService tests pass.

## Context

- **Read task 001's "Findings / Solution" first** — billing route/DTO, non-fatal rule, the `BillingNotificationCreateDTO` `Type`-field mismatch note.
- Files:
  - `SubscriptionService/ServiceCalls/BillingServiceCall.cs` — **currently throws** on non-2xx (this is the fatal anti-pattern). Rewrite `CreateBillingNotificationAsync` to swallow failures (try/catch, optional 800ms timeout) like `LoggerServiceClient.TryLogAsync`. Keep its signature usable; consider forwarding a bearer header param.
  - `SubscriptionService/Controllers/SubscriptionController.cs` — `Create` (line ~42) already calls `_billingServiceCall.CreateBillingNotificationAsync(...)`; `Delete` (line ~122) is the cancellation path with no notification today. Add cancellation notification there.
  - `SubscriptionService/Controllers/SubscriptionPlanController.cs` — only has GET (all/by-id) and POST. **Add `PUT` update.** Add an `UpdatePlan` repo method on `ISubscriptionPlanRepository` if missing.
  - `SubscriptionService/Controllers/PaymentController.cs` — `CreatePayment` (success path) and the catch block (failure path); also `UpdatePayment`. Wire success/fail billing notifications here. The payment DTO carries the subscription/org linkage — resolve the org-id from the payment's subscription (`GetPaymentsBySubscriptionId` / subscription repo).
  - Repo for "subscriptions by plan": add a method like `GetSubscriptionsByPlanId(Guid planId)` to `ISubscriptionRepository` (+ implementation) returning all subscriptions (with `OrganizationId`) on that plan.
- Outgoing DTO: `SubscriptionService/Models/ExternalDTOs/BillingNotificationCreateDTO` currently carries `Text`, `OrganizationId`, `PaymentId`, and `Type = TypeSubject.BillingNotification`. The **receiver** (`BillingNotificationCreationDTO`) only binds `Text`, `OrganizationId`, `PaymentId` — keep the wire body to those three (task 001 contract). `PaymentId` is non-nullable on the receiver; for events without a real payment, pass the relevant payment id or `Guid.NewGuid()` consistent with the existing create call.
- Fan-out is a simple loop over subscriptions-by-plan; one billing call per org. Note batching/dedup as future work (v1 accepts N calls).

## Gotchas
- Making the create call non-fatal is REQUIRED here (the plan calls it out) — don't leave the throwing version.
- Keep the wire body to receiver-bound fields.
- "Cancellation" may be modeled as delete or as a status change — verify against `ISubscriptionRepository` / the entity before assuming; notify on whichever is the real cancel path (and document it in Findings).
- Mock `BillingServiceCall` (or extract an interface) in tests so fan-out count and non-fatal behavior are assertable.
