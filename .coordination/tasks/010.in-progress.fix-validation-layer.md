# Task 010: fix-validation-layer (from review 008 CONCERNS)

**Type:** code
**Dependencies:** 001, 002, 003 (branch off task/003 which merges all three)

## Goal
Make the repo-layer validator the SINGLE source of truth so every invalid signup input returns
`400 { error: "<canonical message>" }`. Today the create DTOs' DataAnnotations + `[ApiController]`
intercept many invalid inputs with `400 { errors: {...} }` and non-canonical messages, breaking the
Shared Contract (see Task 008 findings).

## Acceptance criteria
- [ ] Remove the overlapping format/length/regex DataAnnotations from `OrganizationService/Models/DTOs/UserCreationDTO.cs`
      (the `[EmailAddress]`, password `[MinLength]/[MaxLength]/[RegularExpression]`, username `[MinLength]/[MaxLength]`)
      and `AnonymousUserService/Models/DTOs/AnonymousUser/AnonymousUserCreationDTO.cs` (username
      `[MinLength]/[MaxLength]/[RegularExpression]`, password `[MinLength]/[MaxLength]`).
- [ ] Add `builder.Services.AddControllers().ConfigureApiBehaviorOptions(o => o.SuppressModelStateInvalidFilter = true);`
      in BOTH `Program.cs` (OrganizationService + AnonymousUserService) so any remaining ModelState
      issues fall through to the repo instead of auto-returning `{ errors }`. (Merge with the existing
      `AddControllers()` call — don't double-register.)
- [ ] Null/empty safety so the repo never NREs and always returns canonical messages: in
      `PasswordPolicy.Validate`, treat null/empty as the "too short" canonical message
      (`Password must be at least 8 characters.`). In `UserRepository.CreateUser`, guard null/empty email
      → `ArgumentException("Please enter a valid email address.")` BEFORE `.Trim()`. In
      `AnonymousUserRepository.CreateUser`, guard null/empty username → the canonical username message
      BEFORE `.Trim()`. Keep these edits byte-identical across the two `PasswordPolicy.cs` copies
      (namespace-only diff must still hold).
- [ ] Verify: a request with a missing/empty field, a `[EmailAddress]`-failing email, a too-short/
      too-long password, and a complexity failure (incl. missing-lowercase) ALL now return
      `400 { error: "<canonical>" }` (not `{ errors }`).
- [ ] Update `AnonymousUserServiceTest/AnonymousUserValidationIntegrationTests.cs` to use the strict
      `{ error }`-shape assertion (the test that previously used a substring `Assert.Contains` because the
      annotation layer fired first). Update any unit/integration tests that asserted the OLD annotation
      messages. Re-point any test that depended on `{ errors }` shape to `{ error }`.
- [ ] `dotnet test` for `OrganizationServiceTests` and `AnonymousUserServiceTest`: all validation tests
      pass; the only remaining failures are the pre-existing 401 `[Authorize]` integration tests and the
      stale `DeleteAnonymousUser_DoesNotThrow_WhenNotFound` (do NOT fix those here — out of scope).
- [ ] Confirm the two `PasswordPolicy.cs` files still differ ONLY on the namespace line (run a diff).
