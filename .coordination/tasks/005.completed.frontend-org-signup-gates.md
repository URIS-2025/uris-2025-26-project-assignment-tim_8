# Task 005: frontend-org-signup-gates

**Type:** code
**Dependencies:** 004

## Goal
Enforce the validation policy in the org signup form (`Login.jsx`), fix the stuck-button bug, and
make the helper text honest. Login path keeps only "all fields required" (NO strength gate).

## Acceptance criteria
- [ ] In `Frontend/reporting-app/src/pages/Login.jsx` import `validateEmail`, `validatePassword`
      from `../utils/validation` and `checkPwned` from `../services/pwnedService`.
- [ ] **Fix the stuck-button bug:** `handleSubmit` (`:107-161`) currently calls
      `setIsSubmitting(true)` at line 110 BEFORE the early-return guards (`:122-129`), so a validation
      early-return leaves the button disabled forever. Move `setIsSubmitting(true)` to AFTER all guard
      clauses pass (just before the `try`/service call), OR ensure every early-return path resets it.
      Preferred: don't set submitting until validation passes.
- [ ] **Signup mode only**, add guard clauses after `e.preventDefault()` / `setError('')` and BEFORE
      any network call, in order: `validateEmail(email)` → `validatePassword(password)` → existing
      role/org checks (`:122-129`) → `await checkPwned(password)`: if `'breached'` →
      `setError('This password has appeared in a data breach. Please choose another.')` and return;
      if `'unknown'` → proceed (fail open). On any validator `.valid===false`, `setError(message)`
      and return without a network call.
- [ ] **Login mode:** do NOT run `validatePassword`/`checkPwned`. Keep only a minimal "all fields
      required" guard (email + password present). Existing users may predate the policy.
- [ ] Make the helper text at `:221-223` match the real enforced rule. Current text says "Min. 8
      characters with at least one uppercase letter, digit, and special character" — update to also
      mention lowercase (the regex requires lowercase too), e.g. "Min. 8 characters with uppercase,
      lowercase, a number, and a special character." Keep it concise.
- [ ] Keep the existing inline error block (`:174-184`, `{error && <AlertCircle/>}`) — reuse it; do
      not add a new error UI.
- [ ] `npm run build` succeeds (no lint/compile errors).

## Context
- `handleSubmit` current shape (`Login.jsx:107-161`): sets `setError('')` then
  `setIsSubmitting(true)` (line 110 — the bug), reads `email`/`password`, then in `signup` branch
  checks role/org and calls `UserService.create({...})`; `login` branch calls `UserService.login`.
  The `finally` at `:158-160` resets `setIsSubmitting(false)`, so the bug only bites the guard
  early-returns that happen BEFORE the try (lines 122-129) — those returns skip the finally.
  Moving `setIsSubmitting(true)` below the guards is the clean fix.
- `mode` state distinguishes `'signup'` vs `'login'` (`mode === 'signup'`). Email is read as
  `e.target.email.value.toLowerCase().trim()` (`:112`); password `e.target.password.value` (`:113`).
- The signup `UserService.create` call sends `username: email` — leave that as-is.
- Email/password validators come from Task 004; messages are the canonical ones — do not hand-write
  message strings here, use what the validator returns.
- `checkPwned` is async and returns `'breached' | 'safe' | 'unknown'` — only `'breached'` blocks.
- Do NOT touch AuthContext, routing, or token storage.

## Self-check
- Signup with malformed email or weak password → inline canonical message, NO network call.
- Signup with a breached-but-complex password → breach warning, blocked.
- Validation early-return → submit button is NOT stuck disabled (still clickable).
- Login with any (pre-existing) password → no strength gate, proceeds to `UserService.login`.

## Solution
`Login.jsx`: imported validators + `checkPwned`. Fixed stuck-button bug (moved `setIsSubmitting(true)` after all
guards). Signup-only gates: validateEmail → validatePassword → role/org guards → checkPwned (block only on
'breached', fail open) → service call. Login path: fields-present guard only, no strength gate. Helper text updated
to include lowercase. Reused existing inline error block. `npm run build` succeeded. Branched off task/004.
