# Task 002: rule-controllers-and-errors

**Type:** code
**Dependencies:** 001

## Goal
Write `.claude/rules/controllers-and-errors.md` — how to write a controller in this repo:
attributes, action signatures, the try/catch + `TryLogAsync` audit pattern, and the
`new { error = ... }` response shape. WRONG/CORRECT pairs from real controllers.

## Acceptance criteria
- [ ] File `.claude/rules/controllers-and-errors.md` created, <500 lines, table/WRONG-CORRECT heavy.
- [ ] Findings section lists 3+ real `file:line` occurrences per claimed pattern.
- [ ] Uses real names (`ProblemController.CreateProblem`, `LogCreationDTO`, etc.).
- [ ] Covers: `[ApiController]` + `[Route("api/[controller]")]`; `ActionResult<T>` returns;
      `Created("", result)` / `Ok` / `NoContent` / `NotFound` / `BadRequest`; the audit-log
      call on BOTH success and failure paths; the `new { error = ex.Message }` shape;
      which exception types are caught (`KeyNotFoundException`, `ArgumentException`).
- [ ] Documents the `error` (controller) vs `message` (global handler) key inconsistency as
      a known gotcha — do not "fix" it, just state it.
