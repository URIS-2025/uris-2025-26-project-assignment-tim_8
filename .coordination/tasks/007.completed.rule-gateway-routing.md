# Task 007: rule-gateway-routing

**Type:** code
**Dependencies:** 001

## Goal
Write `.claude/rules/gateway-routing.md` — how to expose a new controller through the Nginx
gateway. Every controller needs a matching `location /api/<Controller>/` block in
`gateway/nginx.conf` with the repeated CORS preamble and a container-name upstream on 8080.
Forgetting this = endpoint unreachable from the frontend.

## Acceptance criteria
- [ ] File `.claude/rules/gateway-routing.md` created, <500 lines.
- [ ] Findings cites 3+ real `location` blocks + the upstream list.
- [ ] CORRECT block template (copy from an existing `location`): the `OPTIONS` 204 short-circuit,
      the 3 `Access-Control-Allow-*` headers (Origin `*`, Methods, Headers `Content-Type,Authorization`),
      and `proxy_pass http://<upstream>/api/<Controller>/;`.
- [ ] Upstream rule: `upstream <name>_service { server <container-name>:8080; }` — container
      names are kebab-case (`problem-service`, `anonymous-user-service`), all port 8080.
- [ ] The proxy headers set once at `server` level: `Host`, `X-Real-IP`, `X-Forwarded-For`,
      `X-Forwarded-Proto` (the last two feed the rate limiter — link rule 006).
- [ ] WRONG/CORRECT: adding a controller without a `location` block; using `localhost`/service
      port instead of the container-name upstream; omitting the OPTIONS branch (CORS preflight fails).
- [ ] Note: CORS is duplicated per-block (no shared map) — adding a block means copying the
      full CORS preamble. Document this, don't refactor it.

## Findings (grep BEFORE writing — record results here)

- Multiple controllers per service map to multiple locations (e.g. Problem, ProblemCategory,

## Context
- Read: `gateway/nginx.conf` (full — it's the only routing file).
- Read: `docker-compose.yml` to confirm container names match upstream `server` names and that

- This explains why frontend API calls go to `http://localhost/api/*` not per-service ports.

## Findings

- `gateway/nginx.conf:17-59` — 11 `upstream` blocks confirmed; all follow the pattern
  `upstream <name>_service { server <kebab-container-name>:8080; }`. Example:
  `gateway/nginx.conf:25-27` (`upstream problem_service { server problem-service:8080; }`),
  `gateway/nginx.conf:17-19` (`upstream anonymous_service { server anonymous-user-service:8080; }`),
  `gateway/nginx.conf:57-59` (`upstream logger_service { server logger-service:8080; }`).
- `gateway/nginx.conf:64-67` — server-level proxy headers set once (`Host`, `X-Real-IP`,
  `X-Forwarded-For`, `X-Forwarded-Proto`), inherited by all 21 `location` blocks.
- `gateway/nginx.conf:70-82` — `location /api/AnonymousUser/`: OPTIONS preflight block with
  `Access-Control-Max-Age 3600; return 204;`, then 3 CORS `add_header` directives outside the
  `if` block, then `proxy_pass http://anonymous_service/api/AnonymousUser/;`.
- `gateway/nginx.conf:139-151` — `location /api/Problem/` (canonical reference block used in
  the rule template): identical preamble structure, `proxy_pass http://problem_service/api/Problem/;`.
- `gateway/nginx.conf:165-177` — `location /api/ProblemComment/` — confirms multiple `location`
  blocks can share one upstream (`problem_service`).
- `gateway/nginx.conf:349-361` — `location /api/Logger/` — last API location block;
  `proxy_pass http://logger_service/api/Logger/;` confirms 11th upstream in use.
- `docker-compose.yml:17-18` — gateway `ports: "80:80"` (only published API port).
- `docker-compose.yml:10-11` — sql-server `ports: "1433:1433"` (only other published port).
- `docker-compose.yml:39-40` — `anonymous-user-service` uses `expose: "8080"`, confirming
  services are NOT individually published on the host; same pattern for all 11 services.

## Solution

The rule file `.claude/rules/gateway-routing.md` (266 lines) documents the complete Nginx
gateway routing contract: every new controller requires a matching `location` block with the
full copy-pasted CORS/OPTIONS preamble and a container-name:8080 upstream, because all 11
backend services are accessible only through the gateway — they are `expose`d (not `ports`-
published) in `docker-compose.yml`, so `http://localhost/api/*` via the gateway is the only
external path.
