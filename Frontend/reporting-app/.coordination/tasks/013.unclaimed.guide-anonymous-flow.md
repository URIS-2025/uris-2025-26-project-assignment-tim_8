`src/services/problemService.js`, `src/services/suggestionService.js`.

Flow to document:
- Public routes (no auth, Navbar layout): `/portal`, `/track`, `/anonymous/signup|login|submit`.
- Anonymous user creates an account (`AnonymousUserService.create`) → logs in
  (`AnonymousUserService.login` → `{accessToken, refreshToken}`) → `AuthContext.login` treats them as
  anonymous because the JWT has no `roleId` (governs the refresh endpoint choice).
- Submitting: `AnonymousSubmit` posts a problem/suggestion (tied to a box via access link).
- Tracking: `TrackReport` looks up a submission by code/id.
- `PublicPortal` browses organizations/boxes/suggestions without auth.

Gotchas: anonymous vs org identity is distinguished by `roleId` absence (see auth-flow guide);
validation is inline (see rule 008-forms-validation). Note box-access-link role.
