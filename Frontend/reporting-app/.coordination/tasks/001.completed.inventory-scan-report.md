## Context
Work from `Frontend/reporting-app/`. Source lives in `src/` (~8,176 LOC across .js/.jsx).
Directory layout:
- `src/pages/*.jsx` (+ some `.css`) — full pages (Admin dashboard, Public portal, Anonymous flows, Billing)
- `src/components/` — `DataTable.jsx`, `Modal.jsx`, `StatusBadge.jsx`, `Navbar.jsx`, `Layout/` (`AdminLayout`, `Sidebar`), `Community/`
- `src/services/*.js` — 21 backend-resource modules
- `src/context/AuthContext.js` — single auth context
- `src/App.js` — all routing + `ProtectedRoute`

Cover in SCAN_REPORT.md:
- Top-level dir structure and what each area owns
- Component architecture pattern (page-based + shared components — confirm)
- State management (local `useState` + `AuthContext`; no global store)
- Data fetching pattern (service modules, `fetch`, error/loading handling in pages)
- Routing setup (`App.js`, `ProtectedRoute`, `Outlet` layouts, route table)
- Styling approach (per-view `.css`, utility classes `glass-panel`/`btn`/`icon-btn`, inline styles)
- Form handling pattern (controlled inputs + manual validation; no form lib)
- Frontend auth pattern (jwt-decode, localStorage `authUser`/`authToken`, silent refresh, role guards)
- 5–10 recurring load-bearing patterns WITH grep evidence
- Proposed rule files (per PLAN.md: services-api, data-fetching-state, routing-guards, auth-context, shared-components, styling, forms-validation)
- Proposed guide files (per PLAN.md: architecture-overview, auth-flow, api-contract-mapping, admin-dashboard, anonymous-flow)

Planner already verified the stack facts in PLAN.md "Stack facts" section — reuse them, but
re-grep to confirm counts before publishing. Useful greps:

## Findings

**Deliverable:** `.coordination/SCAN_REPORT.md` — written and complete. Covers every Context
bullet (dir structure, component/state/data/routing/styling/forms/auth patterns), 12
grep-evidenced recurring patterns (each ≥3 `file:line`), full route table, auth flow table,
7 inconsistencies, and the 7 proposed rule files + 5 proposed guide files (matching PLAN.md,
each with a one-line scope).

**Summary:** Page-based React 19 SPA (CRA). 21 plain-object service modules over raw `fetch`,
single `AuthContext`, local `useState` only. Routing fully centralized in `src/App.js` with a
`ProtectedRoute` wrapper + `Outlet` layouts. Hybrid styling (utility classes + per-view CSS +
heavy inline styles).

**Key confirmed counts (all re-grepped against working tree):**

| Metric | Count | Evidence |
|--------|-------|----------|
| Services with `API_BASE_URL = 'http://127.0.0.1:80'` | 20 | grep `src/services` (21st = `systemUserService.js` uses `https://` — bug) |
| Services with `getAuthHeader` | 2 | `userService.js`, `anonymousUserService.js` only |
| Pages with `useEffect` | 13 | grep `src/pages` |
| Files importing `lucide-react` | 24 | grep `src` |
| Files using `useNavigate` | 14 | grep `src` |
| Pages with `setLoading`/`setError` | 8 | grep `src/pages` |
| `if (!response.ok) throw new Error` in services | 109 / 21 files | escaped grep |

| `glass-panel` references | 69 / 25 files | grep `src` |
| `process.env` usage | 0 | base URL hardcoded, no `.env` |

**Top inconsistencies flagged:** (1) `systemUserService.js` uses `https://127.0.0.1:80` while
all 20 others use `http://`; (2) only 2/21 services send auth headers; (3) mixed per-view CSS
vs 303 inline styles; (4) no `process.env` — URL hardcoded in 21 files.
