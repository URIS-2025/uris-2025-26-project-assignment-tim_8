# Task 004: Rule — routing & route guards

**Type:** code
**Dependencies:** 001

## Goal
Write `.claude/rules/routing-guards.md` covering the routing conventions: all routes declared
in `src/App.js`, the `ProtectedRoute` wrapper, `Outlet`-based layouts, and `useNavigate` usage.

## Acceptance criteria
- [ ] File ≤500 lines, table-heavy, WRONG/CORRECT pairs.
- [ ] ≥3 real `file:line` occurrences cited.
- [ ] Uses real names: `ProtectedRoute`, `AdminLayout`, `Navbar`, `useNavigate`, route paths like `/admin/boxes/:boxId`.
- [ ] Documents nested role guard (`allowedRoles={['admin']}` on `/admin/users`) and redirect targets.

## Context
Read first: `.coordination/SCAN_REPORT.md`.
Read: `src/App.js` (full route tree + `ProtectedRoute` at lines ~28–40), `src/components/Layout/AdminLayout.jsx`.

Confirmed (planner scan, from App.js):
- All `<Route>`s live in `App.js`. Two layout groups: public (wraps `<Navbar/>` + `<main>` + `<Outlet/>`)
  and `/admin/*` (wrapped in `<ProtectedRoute><AdminLayout/></ProtectedRoute>`).
- `ProtectedRoute` reads `useAuth()`; redirects `<Navigate to="/login">` when no user, and
  `<Navigate to="/admin/dashboard">` when role not in `allowedRoles`.
- Role-gated route: `/admin/users` wraps a second `<ProtectedRoute allowedRoles={['admin']}>`.
- Params via `:orgId`, `:boxId`, `:submissionId`. Some routes are pure redirects (`<Navigate replace />`).
- Navigation in components uses `useNavigate()` (14 files).

Rule content (WRONG/CORRECT):
- New protected page → add `<Route>` under `/admin`, not a new Router.
- Use `<Navigate replace />` for redirects, not `window.location`.
- Use `useNavigate()` for programmatic nav; don't mutate `history` directly.
- Role-restricting a page → nest `<ProtectedRoute allowedRoles={[...]}>`.

Evidence greps:
- `grep -rn "ProtectedRoute\|allowedRoles" src/App.js`
- `grep -rln "useNavigate" src`
- `grep -rn "<Route path=" src/App.js`
