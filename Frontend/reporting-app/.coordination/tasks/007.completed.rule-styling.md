**Type:** code
**Dependencies:** 001

## Goal
Write `.claude/rules/styling.md` covering the CSS approach: per-view plain `.css` files,
shared utility classes, and when inline `style={{}}` is acceptable.

## Acceptance criteria
- [ ] File ≤500 lines, table-heavy, WRONG/CORRECT pairs.
- [ ] ≥3 real `file:line` occurrences cited.
- [ ] Uses real class names: `glass-panel`, `btn`, `btn-ghost`, `icon-btn`, `animate-fade-in`, real CSS files like `AdminDashboard.css`, `DataTable.css`.
- [ ] Documents the convention: a page/component imports its own sibling `.css`; global tokens/utilities live in `src/index.css` / `src/App.css`.

Confirmed (planner scan):
- No Tailwind / CSS modules / styled-components. Plain `.css` imported per file
  (`import './DataTable.css'`, `import './AdminDashboard.css'`). 13 page CSS files exist; some pages
  (e.g. `ProblemBoxes.jsx`, `UserManagement.jsx`) have NO sibling CSS and lean on shared/global classes.
- Shared utility classes referenced across components: `glass-panel`, `btn`, `btn-ghost`, `icon-btn`,
  `animate-fade-in`, `clickable-row`, `empty-state` (see `DataTable.jsx`).
- ~22 inline `style={{}}` spots — used for dynamic values (column width/align, cursor, computed colors), not static layout.

Rule content (WRONG/CORRECT):
- Static styling → CSS class in sibling `.css`, not inline `style`.
- Inline `style={{}}` only for runtime-computed values (e.g. `style={{ width: col.width }}`).
- Reuse `btn`/`btn-ghost`/`icon-btn`/`glass-panel` rather than new bespoke classes.
- A new page with significant styling → add `PageName.css` next to `PageName.jsx` and import it.

- `grep -rn "glass-panel\|btn-ghost\|icon-btn\|animate-fade-in" src`
